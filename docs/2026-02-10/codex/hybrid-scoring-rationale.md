# Two-Tower + BM25 하이브리드 점수(0.7 * dense + 0.3 * BM25) 근거 정리

> 작성일: 2026-02-10  
> 대상: CTRPredictor / 추천·랭킹 관련 하이브리드 스코어링

## 목적

Two-Tower(dense)와 BM25(sparse)를 가중합으로 섞는 이유와, `0.7/0.3`이 “일단 안전한 기본값”인 이유를 설명한다.  
현재는 **라벨 데이터가 충분하지 않아(실측 CTR/리라벨 부족)** 최적 alpha를 실험으로 고정하기 어렵기 때문에, **운영 안전성 중심**으로 비율을 선택한다.

## 왜 하이브리드인가

### Dense(두 타워/임베딩)의 강점

- 의미 유사성에 강함(표현이 달라도 비슷한 의도/주제면 점수 상승)
- 롱테일 키워드에 유리

### Dense의 실패 모드

- “키워드/고유명사”가 중요한 쿼리에서 정확히 못 맞출 수 있음
- embedding space에서 가까워도 실제 요구(명시 키워드 포함, 특정 브랜드/상품명 포함)와 어긋나는 결과가 나올 수 있음

### BM25(키워드 매칭)의 강점

- 명시 키워드 포함 요구(상품명/연예인/챌린지/밈 등)에서 강함
- 디버깅 가능(어떤 토큰이 매칭됐는지 설명하기 쉬움)

### BM25의 실패 모드

- 동의어/패러프레이즈에 약함
- 키워드 스팸/중복에 취약

## 왜 0.7 / 0.3 인가 (현재 단계의 “방어적” 근거)

- dense를 과하게 낮추면(예: 0.3) → 의미 기반 일반화가 죽고, 키워드 스팸에 흔들릴 가능성이 커진다.
- BM25를 완전히 빼면(0.0) → 명시 키워드 요구에서 “맞는 말인데 틀린 답”이 늘어난다.

따라서 **dense 중심(0.7) + sparse 보정(0.3)**은 다음을 동시에 만족시키는 기본값이다.

- 의미 유사성(핵심) 유지
- 키워드/고유명사/명시 요구에 대한 안전장치
- 데이터/라벨이 부족한 단계에서 “폭망하는 케이스”를 줄이는 방향

## 추후 실험 계획(라벨 데이터 확보 후)

라벨이 일정 수준(예: 사용자 선택/승인 로그, CTRFeedback 실측) 쌓이면 아래를 실행한다.

1. alpha sweep: `alpha ∈ {0.0, 0.1, …, 1.0}`
2. offline metric:
   - 승인/거부(이진): ROC-AUC, Precision/Recall/F1
   - 실측 CTR(회귀): MAE/MSE
3. 결과:
   - 전체 평균뿐 아니라 “키워드 의존 쿼리 vs 의미 의존 쿼리”로 세그먼트 분리 비교
4. 결론:
   - 최적 alpha(전역) 또는 조건부 alpha(쿼리 타입별) 제안
